## 2. 环境组成

完整业务链路建议准备：

- Python 项目环境
- 数据库：MySQL 或 SQLite
- Redis：Celery 任务队列依赖
- Celery Worker：文档解析任务依赖
- MinIO：文档对象存储依赖
- Elasticsearch：文本切片检索依赖
- DashScope 或 OpenAI 兼容模型服务：Chat / Embedding / Rerank / VLM 依赖
- 本地 ColPali 模型：视觉页图索引依赖

只验证管理页面、租户、模型配置、评测问题维护，可以先使用 SQLite。

## 4. SQLite 本地启动

适合本地快速测试页面和基础功能。

### 4.1 初始化数据库

```powershell
cd "D:\AI02-就业\B-大模型项目\2-rag项目\vlm-rag项目\localGPT-Vision-main"
powershell -ExecutionPolicy Bypass -File scripts\init_sqlite.ps1
```

- 导入 `data\init\sqlite_seed.sql`

```text

```

### 4.2 启动 Django

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_dev.ps1
```

访问：

```text

```

## 5. MySQL 启动

```env
DB_USER=root

```

- 导入 `data\init\mysql_seed.sql`

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_dev.ps1
```

## 6. Celery 启动

文档解析、切片、索引任务需要 Celery。

### 6.1 Docker 容器启动，推荐演示使用

当前环境已按“复用已有基础设施容器”的方式配置 Celery：

- MySQL：`mysql-standalone:3306`
- Redis：`redis:6379`
- MinIO：`minio_oss:9000`
- Elasticsearch：`elasticsearch:9200`
- Celery：`yf-rag-celery`

启动 Celery 容器：

```powershell
cd "D:\01_env\develop\docker\celery"
.\start.bat
```

也可以直接执行：

```powershell
cd "D:\01_env\develop\docker\celery"
docker compose up -d --build yf-rag-celery
```

检查 Celery 是否正常：

```powershell
docker ps -a --filter "name=yf-rag-celery"
docker logs yf-rag-celery --tail 200
docker exec yf-rag-celery celery -A __000__django inspect ping
```

正常结果应包含：

```text
celery@...: OK
pong
```

当前 Celery 容器默认是轻量 Worker，负责普通文档解析、文本切片和 Elasticsearch 索引任务。视觉多模态 ColPali Worker 依赖本地视觉模型和较重的 Torch / Byaldi 依赖，后续如需完整视觉页图索引，可单独启用 `ENABLE_VISION_WORKER=True` 的视觉 Worker。

视觉 Worker 本地进程启动方式：

```powershell
cd "D:\AI02-就业\B-大模型项目\2-rag项目\vlm-rag项目\localGPT-Vision-main"
powershell -ExecutionPolicy Bypass -File scripts\start_vision_worker.ps1
```

注意：该 Worker 需要本机已安装 Torch / Byaldi / ColPali 相关依赖，并准备好本地视觉模型文件。

### 6.2 本地进程启动，备用方式

新开一个 PowerShell：


## 7. 模型 API Key 配置

SQL 种子数据不会写真实 API Key。

启动页面后：

1. 进入“模型管理”
2. 找到“厂商配置”
3. 编辑 `Tongyi`
4. 填写真实 API Key
5. 保存
6. 点击模型列表中的“测试”

也可以使用环境变量兜底：

```powershell
$env:DASHSCOPE_API_KEY="你的 key"
```

## 8. 启动顺序建议

完整链路建议顺序：

1. 启动已有 MySQL / Redis / MinIO / Elasticsearch 容器
2. 初始化数据库和种子数据
3. 启动 Celery 容器 `yf-rag-celery`
4. 启动 Django
5. 配置模型 API Key
6. 打开前端页面测试

当前本机 Docker 演示环境可按下面顺序：

```powershell
cd "D:\01_env\develop\docker\celery"
.\start.bat

cd "D:\AI02-就业\B-大模型项目\2-rag项目\vlm-rag项目\localGPT-Vision-main"
powershell -ExecutionPolicy Bypass -File scripts\start_dev.ps1
```

如果使用 SQLite 快速页面演示，可以不启动 MySQL；但文档解析、任务中心、异步切片索引仍建议启动 Redis、Celery、MinIO、Elasticsearch。

旧的通用顺序是：

1. 启动 MySQL 或使用 SQLite
2. 启动 Redis
3. 启动 MinIO
4. 启动 Elasticsearch
5. 初始化数据库和种子数据
6. 启动 Django
7. 启动 Celery
8. 配置模型 API Key
9. 打开前端页面测试

## 9. 工程自检命令

进入后端工程目录：

```powershell
cd .\localGPT-Vision-main
```

执行基础自检：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_checks.ps1 -SkipPytest
```

该命令会检查：

- Python 核心文件语法
- 前端页面内嵌 JavaScript 语法
- Django system check

如果已安装开发依赖，可以执行完整测试：

```powershell
uv pip install --python .\.venv\Scripts\python.exe pytest pytest-django pytest-cov
powershell -ExecutionPolicy Bypass -File scripts\run_checks.ps1
```

租户隔离数据自检：

```powershell
python manage.py check_tenant_isolation
```

历史 API Key 加密处理：

```powershell
python manage.py encrypt_api_keys
```

该命令会把旧的明文厂商 API Key 转换为签名保护格式；后续通过“厂商配置”保存的新 Key 会自动保护存储。

数据备份：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup_data.ps1
```

数据恢复：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restore_data.ps1 -SqlFile "data\backup\yf_vision_rag_YYYYMMDD_HHMMSS.sql" -DataZip "data\backup\data_files_YYYYMMDD_HHMMSS.zip"
```

Elasticsearch 索引备份：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup_es_indices.ps1
```

Elasticsearch 索引恢复：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\restore_es_indices.ps1 -InputFile "data\backup\es\kb_xxx_YYYYMMDD_HHMMSS.json" -Index "kb_xxx"
```

实验环境默认兼容无登录访问，会自动使用 `default/admin`。如需模拟生产侧显式用户头校验，可设置：

```powershell
$env:REQUIRE_AUTH="1"
```

开启后，访问 `/v1/` 接口需要请求头：

```text
X-Tenant-Id: default
X-User-Id: admin
```

## 10. 常见问题

### 10.1 页面打不开

检查 Django 是否启动成功：

```text
http://127.0.0.1:9380/
```

如果端口占用，可以改用：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_dev.ps1 -Port 9381
```

### 10.2 权限不足

当前默认管理员用户 ID 是：

```text
admin
```

前端“问答对话”中的用户 ID 默认也是 `admin`。如果使用 `viewer` 执行写操作，会返回权限不足，这是正常结果。

### 10.3 文档上传成功但不解析

检查：

- Redis 是否启动
- Celery 是否启动
- Celery 控制台是否报错
- 任务中心是否出现任务

### 10.4 检索调试无结果

检查：

- 文档是否解析完成
- 文本切片数量是否大于 0
- Elasticsearch 是否启动
- Embedding 模型是否可用
- 知识库模式是否包含文本或混合

### 10.5 视觉页图无结果

检查：

- 知识库模式是否是 `视觉多模态` 或 `混合`
- 文档是否生成页图
- ColPali 本地模型路径是否正确
- `data\byaldi`、`data\page_images` 是否生成数据
