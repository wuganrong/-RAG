# 视觉 RAG：从 0 到 1

对照项目：`localGPT-Vision-main`

默认已学过文本 RAG（抽字、切块、Embedding、检索、生成）。本课先换**检索对象**和**打分方式**，再落到企业双引擎业务：知识库、文档台、参数、运维。

一句话：视觉路不抽文本，检索单元是页图，打分用 Late Interaction + MaxSim，生成用 VLM 看这些页；没有页图时回退文本块和文本 LLM。

## 1. 课前概念

本章只补本课陌生的概念。RAG、chunk、Embedding 不再解释。

### 1.1 页图

**是什么：** 文档的一页，整张当成一张图片。不是 PDF 文件本身，也不是从这一页抽出的一段字。

**用来解决什么：** 文本 RAG 的单位是 chunk。表格、公式、扫描件一抽字、一切块就碎。页图把版式、表、图一起留下，后面按「页」检索。

**本项目怎么来：**

1. 图片：本身算一页。  
2. PDF：按页渲染成图。  
3. Word：先转 PDF，再渲染。

### 1.2 多向量

相对你们熟悉的「一段一个向量」。

1. 文本 Embedding：一段话压成一个向量，再做余弦相似。  
2. 页图若也压成一个点：页里的表和公式会被平均掉。  
3. 本项目：一页、一句问都保留一组向量。每个向量对应页上或问句里的一个局部（模型内部的 token / patch）。  

后面图里的「标题 / 表格 / 公式」只是示意，不是人工切了五种元素。

### 1.3 把页图变成向量（相对文本 Embedding）

你们已经会：一段文字进 Embedding 模型，出来一个（或一组）向量，用来检索。

页图也要进索引，必须先变成向量。做这件事的模型，输入是**图**，不是字。可以把它想成「给图片用的 Embedding」：

1. 把一页图切成许多小块（patch）。  
2. 每一块编成一个向量。  
3. 一页因此得到一组向量，对应页上不同位置（字、表、图都在图里，不必先 OCR）。

和文本 Embedding 的差别：

| | 文本 Embedding（已学） | 给页图用的编码 |
|---|---|---|
| 输入 | 一段字 | 一页图 |
| 输出 | 常是一个向量 | 本项目是一组向量 |
| 看见的 | 用词、语义 | 版式、表格线、公式、图上的字 |
| 本课角色 | 文本 RAG 用来建库、查库 | 本项目用来建库、查库 |

它**只负责检索**：把页和问句编到同一空间，供后面打分。它不写回答。写回答的是后面的 VLM（看图说话）。

问句为什么也能送进同一套模型：ColPali 这类模型既能看页图，也能读问句，两边编到同一空间，才能比。

### 1.4 ColPali

本项目里，上面这件事由 **ColPali** 完成。本地权重：`vidore-colpali-v1.2`（PaliGemma 看图底座 + LoRA）。

**做什么：**

1. 建库：把每一页图编成一组向量。  
2. 提问：把用户问句编成一组向量。  

两边必须同一套 ColPali，空间才一致。后面的 MaxSim 比的就是这两组向量。

### 1.5 Late Interaction（晚交互）

1. 你们熟悉的打分：问句一个向量、文档一个向量，比一下结束。这是先压缩、再交互。  
2. Late Interaction：先不压成一个点。问句侧、文档侧都留多个向量，到打分这一步才两两对齐。  
3. 好处：问句里的「金额」可以对上页里那一块表，而不是和整页平均分死磕。

### 1.6 MaxSim

Late Interaction 在本项目里的具体算法。

1. 问句的每个向量，在该页所有向量里找最像的一个（取最大相似度）。  
2. 把这些最大值聚合成这一页的分。  
3. 每一页都算一遍，按分排序，取前 k 页（默认 3）。

### 1.7 Byaldi

**是什么：** 管 ColPali 页向量和页图的检索库。不是另一种 Embedding 模型。

**做什么：**

1. `index`：写入索引。  
2. `search`：跑 MaxSim。  
3. 页图随库存下（`store_collection_with_index=True`），取回时才能还原成图，交给 VLM 和页面。

## 2. 文本 RAG 和多模态 RAG

### 2.1 换了哪三处

文本 RAG 已经会：chunk → 文本向量 → 相似检索 → LLM 读文字。

本项目仍是「先检索再生成」，只换三处：

1. 单位：页图。  
2. 检索：Late Interaction + MaxSim。  
3. 生成：VLM 看检索到的页，不读 chunk。

### 2.2 六个维度对照

| 序号 | 维度 | 文本 RAG | 本项目 |
|---|---|---|---|
| 1 | 对象 | 文本块（chunk） | 文档页图 |
| 2 | 入库 | 抽字 → 切块（常要 OCR） | 渲染成页（检索不做 OCR） |
| 3 | 表征 | 一段一个向量 | 一页一组向量 |
| 4 | 检索 | 向量相似 / 关键词 | Late Interaction + MaxSim |
| 5 | 生成 | 读文字片段 | VLM 看检索到的页图 |
| 6 | 证据 | 引用一段话 | 展示那几页图 |

![图 2-1 同一份文档，两条路](https://2026-bucket.oss-cn-wuhan-lr.aliyuncs.com/marktext/2026/09/13/20260913025624211_0a2600d45a78422196fa9e52c5655d7b.png)

### 2.3 什么时候仍用文本 RAG

1. 扫描件、表格、公式、双栏：文本 RAG 容易碎，适合视觉路。  
2. 纯制度条文、只要关键词：文本路更轻，不必把整页当图再编码。  
3. 同一库两种材料都有：建库选 **hybrid**，提问按「有页图只用页图」分流。

## 3. 项目完整流程

画的是事怎么走，不是接口怎么发。

### 3.1 总图

![图 3-1 事怎么走](https://2026-bucket.oss-cn-wuhan-lr.aliyuncs.com/marktext/2026/09/13/20260913025625047_a3f35a7c33d142549703a3c3ffd8c409.png)

读图：竖线「查」是 **索引 → 最相关的 3 页**（问句向量与索引里每一页做 MaxSim）。不是索引直接连到「回答」。回答是 3 页图 + 问题交给 Qwen-VL 之后的事。

### 3.2 现在是双引擎

视觉线没变：

1. **建库：** 文档 → 页图（渲染）→ 页向量（ColPali）→ 索引（Byaldi，按知识库一份）  
2. **提问：** 问题 → 问句向量（ColPali）→ MaxSim → 最相关页 → Qwen-VL

文本线（`text` / `hybrid` 才建）：

1. **建库：** 文档 → 抽字 → 切块 → Embedding → ES（或本地向量回退）  
2. **提问：** 关键词 + 向量 → 文本块 → `qwen-plus`

提问规则（写在 `__005__retrieval/fusion.py`）：

1. `vision`：只查页图，VLM 作答。  
2. `text`：只查文本块，文本 LLM 作答。  
3. `hybrid`：两路都查。有页图则 VLM 看页，文本块作为补充；没有页图才走文本 LLM。

### 3.3 切两刀

1. **建库 / 提问：** 对应总图两行。没建库，内存里没有这份索引，不能问。  
2. **检索 / 生成：** 检索到选出 3 页为止。生成从「页图 + 问题 → Qwen-VL」开始。VLM 看的是检索页，不是用户刚上传的原件。

### 3.4 两个边界

1. 重启后内存空了，索引还在磁盘，先载入再查。  
2. 生成挂了（例如连不上云），检索仍可能已经成功。

## 4. 检索原理

口诀：**渲 → 编 → 存 → 询 → 配 → 取**

前三字建库，后三字提问。生成（Qwen-VL）不在六字里。

### 4.1 渲：变成可以看的页

**是什么：** 把文件变成「一页一张图」。检索单元是页图，不是 PDF 字节，也不是一段字。

**怎么做：**

1. 图片：本身就是一页。  
2. PDF：Byaldi 用页渲染（pdf2image）按页出图。Windows 上这一步需要 Poppler（`pdftoppm`）。  
3. Word（`.doc` / `.docx`）：`converters.py` 先转成 PDF，再走第 2 步。这不是 Poppler 的工作。

### 4.2 编：一页变成一组向量

**是什么：** 用 ColPali 看页图，输出一组向量。不把整页压成一个点，所以表、公式、标题可以分别被问句对上。

**怎么做：** 本地 `vidore-colpali-v1.2`（PaliGemma 视觉底座 + LoRA）。页图进模型，出来多个向量。下图是示意，不是「五种版面元素各一个向量」。

![图 4-1 编：一页不是一个点](https://2026-bucket.oss-cn-wuhan-lr.aliyuncs.com/marktext/2026/09/13/20260913025645090_4d2205b4e19a46b8a0c9f1f106db0593.png)

### 4.3 存：写成下次还能查的库

**是什么：** Byaldi 索引。里面是各页的多向量；同时把页图存进去，后面才能还原给 VLM 和页面。

**怎么做：** `indexer.py` 里 `RAG.index(..., store_collection_with_index=True)`。关掉这个开关，检索还能打分，但「取」没有图。索引落在 `data/byaldi/<知识库id>/`，**一份知识库一份索引**，不是一份会话一份。

### 4.4 询：问句也变成一组向量

**是什么：** 用户那句话同样用同一套 ColPali 编码。

**怎么做：** 不另训一个文本 Embedding。必须同一模型、同一空间，后面的 MaxSim 才比得起来。空间不同，分数没有意义。

### 4.5 配：给每一页打分

**是什么：** Late Interaction + MaxSim。定义见 1.5、1.6。

**怎么做：**

1. `retriever.py` 调用 `RAG.search(query, k=3)`。  
2. 对索引里每一页都算一遍页分，再按分排序。  
3. 下图只画「一页内部怎么取最大」；真实还要「页和页比完，取最高的 3 页」。

![图 4-2 配：MaxSim](https://2026-bucket.oss-cn-wuhan-lr.aliyuncs.com/marktext/2026/09/13/20260913025625449_7a1bae2664a548d496e292ff679476fa.png)

### 4.6 取：分数变成能看的 3 页

**是什么：** 把 Top-K 页从索引里还原成图。

**怎么做：**

1. `search` 带回页图的 base64（建库时存了 collection）。  
2. 解码成 PNG，写到 `data/page_images/<知识库id>/`，页面用 `/media/pages/...` 读。  
3. 同一批图两条去向：送给 Qwen-VL 作为生成依据；显示在回答下面作为证据。点引用也能打开原文页。

没有「取」，界面上只剩一段字，看起来会像普通文本问答。

### 4.7 六字对照

| 序号 | 字 | 阶段 | 谁做 | 关键点 |
|---|---|---|---|---|
| 1 | 渲 | 页图化 | Byaldi 渲染页；Word 先经 `converters.py` | Poppler 只服务 PDF→页图 |
| 2 | 编 | 页 → 多向量 | ColPali（`indexer.py` 加载） | 一页多个向量，不是一个点 |
| 3 | 存 | 写入索引 | Byaldi `index` | `store_collection_with_index=True` |
| 4 | 询 | 问句 → 多向量 | 同一套 ColPali | 和页在同一空间 |
| 5 | 配 | 页打分、排序 | Byaldi `search` | 每页 MaxSim，再取 top-k |
| 6 | 取 | 还原 3 页图 | `retriever.py` | 图给 VLM，也给前端 |

## 5. 企业业务

视觉原理没变。落地时必须把「会话」和「库」拆开，否则换个聊天窗口就像换了一个库。

### 5.1 三条边界

| 对象 | 管什么 | 不管什么 |
|---|---|---|
| 知识库 | 文档、索引、检索模式、召回参数 | 某一次问答的措辞 |
| 文档 | 上传、建索进度、去重、删除 | 聊天记录 |
| 会话 | 问答历史、引用 | 索引落在哪 |

Cookie 会话只记「当前登录人 / 当前库 / 当前对话」，**不是索引边界**。同一知识库下的多个会话共用一份索引。

### 5.2 三种建库模式

建库时选，写在知识库字段 `rag_mode`：

| 模式 | 建什么 | 提问时怎么走 |
|---|---|---|
| `text` | 抽字、切块、Embedding、ES/本地向量 | 只回文本块，文本 LLM 作答 |
| `vision` | 页图 + ColPali | 只回页图，VLM 作答 |
| `hybrid` | 上面两路都建 | **有页图：VLM 看页，文本块作补充依据；无页图：只走文本 LLM** |

改 `rag_mode` 不是只改一个字段：对不上的那路索引会删掉，库内文档会按新模式重新建索。文档上会写下当时的 `index_modes`。

不要把 ColPali 的多向量塞进 ES 的稠密字段。ES 只服务文本路。

### 5.3 工作台四页（对应企业五块）

| 页 | 对应 | 做什么 |
|---|---|---|
| 对话 | 业务实现 | SSE 问答；有页图出页图；点引用看原文 |
| 文档 | 业务需求 | 上传、进度、失败重试、删除；文档属于当前库 |
| 参数 | 模型参数 | 模式、`top_n`、`page_top_n`、阈值、Embedding、LLM/VLM |
| 运维 | 架构 + 工程 | ColPali / DashScope / Redis / ES / MinIO、配额、审计；探测才打远端 |

角色：`viewer` 只能问；`editor` 能上传删除；`owner` 能删库。日配额超限直接拒绝，计数超限会回滚。

### 5.4 建库流水线

1. 登录后进 **文档** 页，不要在对话页夹文件。  
2. 文件先落本地工作副本，再镜像 MinIO（局域网不通就只留本地）。  
3. 同库同 SHA256 且已建完的文件不再占 GPU。  
4. 后台单线程建索：`text` 切块写入；`vision` 增量写入 Byaldi；文档记下 `index_modes`。  
5. 状态：`0` 待建索 / `2` 建索中 / `1` 已完成 / `-1` 失败。失败可重试（会清 `page_num` 再写视觉）。  
6. 删除文档：文本块 / ES / 向量立刻删。Byaldi 不能按文档摘页，所以用剩余文件**整库重建**视觉索引，避免删了还能搜到旧页。  
7. 改模式：丢掉不再需要的引擎，剩余文档重新入队建索。

文本模式遇到纯图片会直接失败，提示改视觉或混合。Word 转 PDF 需要本机 Word，失败时直接上传 PDF。

### 5.5 提问流水线

1. 当前库至少有一份 `run=已完成` 的文档，否则不生成。  
2. `fusion.py`：`vision` 只查页；`text` 只查块；`hybrid` 两路都查。  
3. 有页图：页图给知识库 `vlm_id`（默认 Qwen-VL）；`hybrid` 时文本块作为补充上下文。  
4. 无页图：文本块给知识库 `chat_id`（默认 `qwen-plus`），SSE 逐 token。  
5. 引用和页图写回会话，点得开。

### 5.6 工程约束（课上要讲清楚的取舍）

已落地：懒加载回退、同库去重、改模式重建索引、删文档重建视觉索引、配额回滚、审计、`vlm_id`/`chat_id` 真正进生成、SQLite 给后台线程用。

刻意没做：Celery Chord、K8s、SSO、病毒扫描、Byaldi 官方仍未实现按页删除（本项目用重建代替）、意图识别。这些不是「写了字段就算有」。

## 6. 项目启动和测试

### 6.1 启动

#### 6.1.1 环境

在 `localGPT-Vision-main` 项目根目录准备：

1. Python 虚拟环境已创建，并已安装 `requirements.txt`。  
2. **PDF → 页图**需要 Poppler（`pdftoppm` 在 PATH 中）。Word 转 PDF 另要本机 Word。  
3. 上一级目录 `vlm-rag项目/models/` 中已有：  
   - `vidore-colpali-v1.2`  
   - `vidore-colpaligemma-3b-pt-448-base`  
4. 项目根目录 `.env` 已填写有效的 `DASHSCOPE_API_KEY`。国内 DashScope 默认直连，不要走已挂掉的本机代理。

#### 6.1.2 启动服务

1. 打开终端，进入项目根目录 `localGPT-Vision-main`。  
2. 用该环境的 Python 执行：`python app.py`。  
3. 终端出现 `Running on http://127.0.0.1:5050`，并提示 Local ColPali ready。  
4. 浏览器打开 `http://127.0.0.1:5050`，登录 `admin` / `admin123`。  
5. 侧栏进 **参数**：检索选本地 ColPali v1.2，生成选 Qwen-VL，知识库模式按材料选 `vision` 或 `hybrid`，保存。

### 6.2 测试

按业务功能测。材料尽量用带表格、公式或扫描件的 PDF / 图片；纯文字讲义观感会像普通 RAG。

#### 6.2.1 未建库提问（负例）

1. 空知识库或文档未建完。  
2. 在 **对话** 页直接提问。  

**期望：** 提示当前知识库还没有完成建索的文档。聊天区不应假装生成答案。

#### 6.2.2 上传并建库

1. 进 **文档** 页，选择 1 份 PDF 或图片（建议 1～3 页），提交建索。  
2. 等状态从「建索中」变为「已完成」（首次加载 ColPali 可能要几分钟）。  

**期望：** 进度条走动；失败可点重试。侧栏配额「上传」加 1。

#### 6.2.3 问答（主路径）

1. 建库成功后进 **对话**，不要重新上传。  
2. 问一句和文档内容相关的话（标题、表格数字、图上模块名）。  
3. 等待流式结束。  

**期望：**

1. 有文字回答，内容对得上文档，不是空泛百科。  
2. 下方有检索页图（最多 `page_top_n` 张），点开能放大。  
3. 点引用能打开页图或文本原文。  
4. 有页图时走 VLM；纯文本库走文本模型。

#### 6.2.4 同一库连续提问

1. 不换知识库、不再上传。  
2. 再问一个同一文档上的不同问题。  

**期望：** 仍能出文字 + 依据。不同问题取回的页可以不同。

#### 6.2.5 知识库隔离（不再按会话隔离索引）

1. 侧栏 `+` 再建一个知识库，模式可另选。  
2. 不上传，先提问。  
3. 在新库 **文档** 页上传**另一份**材料并建完，用新材料提问。  
4. 切回旧库，用旧材料提问。  

**期望：** 新库未建完时与 6.2.1 相同。建完后只答新库。切回旧库仍答旧材料，两库不串台。同一库下新建会话，索引仍在，只是聊天记录空了。

#### 6.2.6 参数和运维
